# SNORR Firmware 0.1.0

Established by the owner on 2026-10-23 as the current development baseline.
Major version zero denotes development; no beta suffix is used. First accepted
production release will be 1.0.0. Subsequent fixes use 0.1.1, while the next
development feature milestone uses 0.2.0.

## Source baseline

- Repository: `lfg-seth/firmware`, branch `snorr/rak-survey`.
- Exact source: `5c2c1adad098eea1e4795158d19c9debe306eded`.
- Upstream baseline: Meshtastic `2.7.26.54e0d8d`.
- Product version: **SNORR 0.1.0**, distinct from device-reported Meshtastic versions.
- Status: recorded source/fleet baseline, not a newly built or uniformly deployed
  artifact set. No existing binary, runtime string or release tag is rewritten.

## Initial changelog

This initial entry captures existing work, rather than changes made today:

- RAK AHT detection compatibility (optional NCP5623 RGB support disabled).
- Shared passive SNNS neighbor reporting for RAK and the dedicated V3 gateway
  target, including RSSI/SNR, hearing age/counts and bounded storage/reporting.
- Corrected INA219 environment/power handling, channel-1 power reporting,
  failed-read rejection and consistent current multiplier handling.
- Ordinary RAK 180-second SNNS baseline with jitter and airtime gates.
- Separate opt-in INA219 diagnostic, R005 load and receive-only sniffer targets.
- RAK artifact manifest/checksum and release tooling; latest public release
  publication remains pending. Gateway production hardening remains unfinished.

## Limits and next release

SNNS still lacks an absolute source timestamp; its RAK interval is compiled in.
Remote-admin setup/acceptance, gateway TLS/logging/reconnect fixes, calibrated
power readings, sustained runtime and field readiness remain outstanding.
R006's latest image is an explicitly verified local bundle, not a published
production release. Current 0.1.0 does not claim these future fixes.

[LOCAL-6](../../.scratch/pilot/issues/28-snorr-firmware-releases.md) owns future
product-version embedding, coordinated per-target manifests/builds, changelogs
and installed-fleet accounting. LOCAL-3 and LOCAL-4 supply RAK/shared and gateway
work. Any changed source or newly produced artifacts receive a new release
identity; keep this initial baseline immutable. A fresh install claim must name
its exact target artifact and verification evidence.
