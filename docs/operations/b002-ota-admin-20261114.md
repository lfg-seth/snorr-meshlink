## Method and evidence

Only B002's USB port was opened. Target identities, public keys and B002 admin
enrollment were checked against their complete saved batch readbacks. The
station OS lease excluded a concurrent label-station process during the run;
its saved heartbeat was stale before testing. The ordinary sandbox could not
open COM4; the approved serial-access retry completed the test.

Each request was a PKI-encrypted ADMIN_APP device or telemetry configuration
read, with a fresh packet ID, zero outgoing hops, acknowledgement/response
requested and a 22-second deadline. Requests ran sequentially with three-second
spacing after each response. Pass required the exact target source and request
ID, an encrypted response, and the expected protobuf configuration variant.
An acknowledgement alone did not count. All six requests passed without an
application-level retry; the run does not measure firmware radio retry counts.

B002's complete owner, local/module/channel configuration and keys matched
before/after snapshots. No configuration writes, reboot commands, flashing,
role changes, portal changes or target USB access occurred. The B002 serial
handle and station lease were released at handoff.

Ignored evidence: `private/bench/b002-ota-admin-20261114/` contains the
read-only harness, `summary.json`, six private response packets, private SDK
log and B002 before/after profiles. Target enrollment/key references came from
`private/bench/rak-batch-20261113T034943Z/` per-board `current-readback.json`.

## What this establishes and what remains

B002 can authenticate and read settings over LoRa on these three current
repeaters. This is direct-request-path acceptance, not forced-relay acceptance
or a sustained reliability measurement. It does not test the other seven
repeaters. Saved telemetry intervals do not establish actual delivery cadence
or sensor presence.

The earlier [admin bench](repeater-update.md#r006-and-gateway-admin-bench---2026-10-24)
demonstrated writes on a historical R006 assignment but found reboot/session
acknowledgement ambiguity. Today's read-only test does not clear that limitation
or establish safe current-fleet writes. Next: select a reversible configuration
write with independent readback/restoration, then test a forced relay excluding
direct reception and interrupted/lost-command handling before inaccessible use.
